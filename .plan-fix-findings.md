# Plan: Fix Verification Findings

## Context
During runtime verification of Clawde v0.1.0, several code quality issues were identified: dead code, unreachable statements, stale comments, and vestigial references to removed features. These don't break the app but create confusion for maintainers and represent incomplete cleanup from previous refactors (hunger/sleep removal, movement system decoupling). This plan addresses all findings from the verification report.

## Changes

### 1. Remove unreachable code in `_draw_body()`
**File:** [renderer.py](clawde/renderer.py:321-332)

Delete lines 321–332 (the second `return` dict that can never execute). The first return at line 313 is the correct one — it includes `"head"`, `"left_eye"`, `"right_eye"`, `"left_arm"`, `"right_arm"` which are all the keys actually used by callers (`_draw_hat`, `_draw_hydration_bubble`, state draw functions). The dead block adds `"body"`, `"left_leg"`, `"right_leg"` keys that nothing reads.

### 2. Wire up `MovementController` or remove it
**File:** [movement.py](clawde/movement.py), [app.py](clawde/app.py)

The `MovementController` class implements walking, hiding, and safehouse logic but is never instantiated. The `WALKING` state exists in the state machine and has a draw function, but can only be triggered if something sets it. Two options:
- **Option A (Recommended): Wire it up.** Import `MovementController` in `app.py`, instantiate it in `__init__`, call `update()` in `_tick()`, and connect `notify_drag_released()` to the renderer's mouse release. Also set `renderer.set_hiding()` based on `movement.is_hiding`. This activates the already-implemented autonomous movement behavior.
- **Option B: Remove the file.** Delete `movement.py` entirely and remove the `WALKING` state from `state_machine.py` and `renderer.py`.

→ **Going with Option A** since the code is complete and tested-looking; it just needs wiring.

Specific changes in `app.py`:
- Import `MovementController` from `.movement`
- Create `self._movement = MovementController()` in `__init__`
- In `_tick()`: call `new_x, new_y = self._movement.update(ctx, rx, ry, self._renderer.is_dragging, new_state.name)` and apply via `self._renderer.move(new_x, new_y)` (replacing or supplementing `_position_panel`)
- In renderer's `mouseReleaseEvent`: call `app._movement.notify_drag_released()` (need to pass callback or expose movement to renderer)
- Call `self._renderer.set_hiding(self._movement.is_hiding)` each tick
